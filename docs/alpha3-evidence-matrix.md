# `v0.1.0-alpha.3` — Release Evidence Matrix

**Rule (alpha.3 §32.1):** a checklist item without named evidence is not PASS.

`node scripts/evidence.ts` parses this table and fails the build on any `PASS`
with an empty evidence cell, any evidence reference with no recognised prefix,
any `test:`/`suite:` naming something that appears nowhere under `tests/`, and
any `artifact:` pointing at a file that does not exist. It does **not** run the
tests — CI does that. It checks that the claims point at something real, which
is the half alpha.2 was missing.

Status vocabulary is exactly four values:

| Status           | Meaning                                                       |
| ---------------- | ------------------------------------------------------------- |
| `PASS`           | A named, executable piece of evidence asserts it.             |
| `FAIL`           | Known broken. The evidence cell names what shows the failure. |
| `NOT TESTED`     | Not asserted here. The notes column says why, and what would. |
| `NOT APPLICABLE` | Out of scope for this milestone.                              |

Evidence prefixes: `test:` `suite:` `ci:` `eval:` `artifact:` `live:` `manual:`.

> **The SSH rows come from a real remote machine.** `pnpm test:ssh` was run
> against a separate aarch64 Linux VM over the network (49 pass, 0 fail, 1
> loopback-only skip), and again against a loopback `sshd` (50 pass, 0 fail).
> Both are real OpenSSH. What is still **not** claimed: cross-host OS isolation
> — the workspace jail is a path check, not a boundary — and hostile-network
> behaviour. See `docs/alpha3-ssh-validation.md`.
